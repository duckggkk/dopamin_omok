
### 회고록의 작성 이유
- 내가 부족한 점을 객관적으로 정리하고 그 부족한 점들을 메우며 안 써본 스택들을 도입하고자 하는것이 이번 '도파민오목' 프로젝트이다.

- 김영한 강사는 수업만 듣는것보다 직접 프로젝트를 경험 하는 것이 더 효율적이라고 했으며 이것은 나역시 체득이 된 부분이다. 이에더해 단순히 프로젝트만 진행하는것보다 내가 의문점이 들었던 부분을 글로 정리하는것이 더 명료히 이해가 되는 부분이 있기때문에 작성하게 되었다

- 또한 작성된 코드들을 검토하다가 비효율적이거나, 기존의 지식과 다르거나, 의문점이 생기는 부분이 있었으며 이를 해결하는 과정에서 다시 한번 공부가되어 글로 남기게 되었다.

- 또한 초기 목표를 설정하고 이를 잘 달성했는지 스스로 평가하려고 한다.


# 1. 개발 목표
1. 이전 프로젝트는 클린아키텍처를 구현할 시간이 부족했다. 물론 모든 상황에서 SOLID원칙을 완전히 지키는게 가능한 것도 아니고 정답이 아니라는 것은 알고 있지만 해본 것과 안 해본것의 차이는 분명히 크고, 프로젝트를 진행하면서 얻는 것이 있을 것 이기때문에 진행한다. 목표는 '헥사고날 아키텍처'을 구현함으로서 클린 아키텍처의 이해도를 한층 끌어 올리는것을 목표로 한다.

2. 이전 프로젝트에서 개발만큼 중요한 것이 협업, 기획자 및 유저 입장에서 생각해 보는것임을 깨달았다. 이 서비스가 과연 지속적인 수익을 유지할 수 있는지, 유저 입장에서 불편한 점이 무엇인지 견문을 넓히는 것을 목표로한다.

4. 이전 프로젝트에선 백엔드만 담당하였는데 현 프로젝트에선 React를 깊게 다뤄보는것을 목표로 한다.
- UI보단 리액트 빌드 방식으로 인한 특징, 효율적인 컴포넌트 사용, 전역변수의 생명주기와 스토리지의 이해를 목표로 한다.

5. 이전 프로젝트에선 테스트에 투자할 시간이 부족하였다. 현 프로젝트는 클린 아키텍처를 목표로 하는만큼 유닛 테스트를 적극 활용하고 일관적이고 회귀적인 테스트 결과를 목표로 한다.

6. 수동 배포는 충분히 해왔으므로 github Actions을 통한 자동 CI/CD를 사용하고자 한다.

7. 이전 프로젝트에선 넉넉한 서버 자원으로인해 상대적으로 자원 관리가 용이했다. 이번 프로젝트는 적은 자원을 활용하므로 서비스 운영에 따른 트래픽과 메모리 관리에 대한 이해도를 높이는 것을 목표로 한다.

8. DB 혹은 특정 외부 인프라를 실제로 교체하며 클린아키텍처의 의의와 각 인프라 효율등을 비교하는 것을 목표로 한다.

9. 실서비스 공부를 위한 서비스이기 때문에 오버 엔지리니어링임을 명심한다.

10. 도메인 서비스를 산 후, 실제 서비스를 운영하여 가능하다면 운영 경험치를 쌓는 것이 2차 목표이다.



# 2. 공부 방향
1. 레퍼런스와 AI의 보조를 받되, 스택과 설계는 직접 결정하고 다른 방안이 있는지 여러면에서 검토한다.
2. 백엔드의 경우 Config로 시작해서 Spring security등 추상화를 적극활용한 코드들을 뜯어보며 SOLID 원칙에 대한 이해도를 높인다. 또한 커스텀을 적용해본다.
3. 라이브러리나 API의 경우 다른 방안이 있나 탐색해본다.
4. 단순히 기술을 사용하는 것이 아니라 공식 문서와 라이브러리의 코드를 깊이 파고들며 코드 읽는 눈을 높이고 어떤 방식을 사용하는지 이해한다.
